## 1. Offset-RMSNorm application — CORRECT (PROVEN)

**Deployed code path.** `vllm/model_executor/models/qwen3_5.py:39` imports `GemmaRMSNorm as Qwen3_5RMSNorm`; it is instantiated for `input_layernorm`/`post_attention_layernorm` (qwen3_5.py:181–186), the final `norm` (qwen3_5.py:264), and — via `Qwen3NextAttention` — `q_norm`/`k_norm` at head_dim 256 (`qwen3_next.py:315–316`). `GemmaRMSNorm` (`layers/layernorm.py:131–167`) computes `weight = self.weight.float() + 1.0` then `ir.ops.rms_norm(x, weight, eps)`; the IR native implementation (`vllm/ir/ops/layernorm.py:9–21`, and `fused_add_rms_norm` 43–62 for the residual form) does: x→fp32, variance in fp32, `x·rsqrt(var+eps)`, multiply by the fp32 `(1+w)`, single final cast to bf16. This is exactly **rmsnorm(x)·(1+w)**.

**Fused/kernel paths cannot subvert it.**
- IR dispatch: `IrOpPriorityConfig` (config/kernel.py) installs the priority via `set_default()`; CUDA default is `["native"]` whenever Inductor compilation is on (`platforms/cuda.py:689–707`) — matching the engine's reported `rms_norm ir_op_priority "native"`. VERIFIED-BY-READING.
- Even under the non-compiled priority `["vllm_c","native"]`, the `vllm_c` CUDA kernel's `supports_args` requires `weight.dtype == x.dtype` (`vllm/kernels/vllm_c.py:17–20`); the Gemma path always passes an fp32 weight with bf16 activations, so dispatch structurally falls through to native. The raw kernel (which computes `x·w`, not `x·(1+w)`) is unreachable for these norms. PROVEN by reading the guard.
- The fused `fused_qk_rmsnorm_rope_gate` Triton path receives `q_norm.weight.float() + 1.0` explicitly (qwen3_next.py:351–352) and multiplies the passed weight without re-offsetting (`layers/fused_qk_norm_rope.py:64–67`) — no double offset. In this deployment it is **disabled anyway**: `use_fused_qk_norm_rope_gate` requires text-only (`qwen3_next.py:320–327`) and the vision tower is loaded, so the eager GemmaRMSNorm + MRoPE path runs.

**Reference equivalence (executed probe, `norm_probe.py`).** Against the deployed HF reference `transformers/models/qwen3_5/modeling_qwen3_5.py:720–737` (`output = rmsnorm(x.float()) · (1.0 + w.float())`), using **real restored weights read from the checkpoint** (`layers.0.input_layernorm`, `layers.3.self_attn.q_norm`, final `norm`) at activation scales 0.02/1.0/30: vLLM-native output is **bit-identical to HF in all 9 configurations**. PROVEN.

**Site census (executed).** Reading the safetensors header of `Qwen3.8-27B-NVFP4-Corrected/model.safetensors`: 64 input + 64 post-attention + 16 q_norm + 16 k_norm + 1 final = **exactly 161 offset-parameterized tensors** — the restored set. The 48 `linear_attn.norm` tensors use the *plain* gated parameterization: vLLM `RMSNormGated` (`qwen_gdn_linear_attn.py:467–474` → `layernorm.py:172–307`, CUDA path `third_party/flash_linear_attention/ops/layernorm_guard.py`, all-fp32, `out = rmsnorm(x)·w·silu(z)`), matching HF `Qwen3_5RMSNormGated` (modeling_qwen3_5.py:168–184). Probe `gated_norm_probe.py`: the real `layers.0.linear_attn.norm.weight` sits at mean 0.869 (≈1, ones-centered — offset storage would sit near −0.13), and vLLM-vs-HF differ ≤1 bf16 ulp (HF inserts a mid-stream bf16 cast; vLLM stays fp32 — vLLM is the more precise of the two). The vision tower uses `nn.LayerNorm` (qwen3_vl.py:478–480) — a separate lineage, BF16, untouched. So the 161-count is *closed*: every offset site is offset-applied, every non-offset site is plain-applied. PROVEN.

**What the wrong form would do (derivation + probe).** With offset-stored weights (median |w| = 0.0332 at layer-0 input norm), `rmsnorm(x)·w` multiplies the normalized stream by ≈w: measured output RMS ratio wrong/correct = **0.055** (layer-0 input), 0.196 (q_norm), 0.489 (final). A 5.5% amplitude collapse with per-channel sign flips at the first of 129 decoder norm applications destroys the forward pass; the deployment's live validation record (tool loops, exact-pixel OCR, 11/11 SWE-rebench) is impossible under the wrong form. Conversely the correct form is anchored, not inferred: the stored bytes equal the official offset weights (established restoration) and the official reference itself applies (1+w). PROVEN.

Benign deviation noted: `fused_add_rms_norm` adds the residual in fp32 and normalizes the fp32 sum (HF normalizes the bf16-rounded sum); the residual stream stored back is `bf16(x+res)`, identical to HF (probe-verified). ≤1-ulp class, precision-improving.

## 2. TurboQuant K8V4 KV cache — implementation CORRECT; error budget derived

**Configuration (PROVEN from `quantization/turboquant/config.py:20–41,128–174`).** Preset `turboquant_k8v4`: FP8 keys (no rotation, no MSE, no norm correction), 4-bit values. At D=256: key 256 B + value 128 B + fp16 scale 2 B + fp16 min 2 B = **slot 388 B, no padding** (388 even). 388·4 heads·16 layers = 24,832 B/token; ×262,144 = **6,509,559,808 B = 6.0625 GiB** — matches README exactly. Hybrid models get no boundary-skip layers (config.py:193–201): all 16 full-attention layers quantized. The Hadamard/centroid tables are built but unused on the K8V4 path.

**Quantization math (PROVEN from `ops/triton_turboquant_store.py`).** Per token, per head, per 256-vector:
- **Keys** (lines 188–194): bf16 → fp32 → FP8 **E4M3** (`tl.float8e4nv`; `_use_fp8_e4b15` selects e4b15 only for SM < 8.9 — this GPU is SM 12.0, so e4nv; `triton_turboquant_decode.py:25–35`), byte-stored by bitcast. No per-vector key scale: absolute E4M3 encoding, RN-ties-even, saturating (`cvt.rn.satfinite` semantics; torch's `float8_e4m3fn` cast in-container confirmed saturation at ±448, subnormals to 2^-9, below → 0).
- **Values** (lines 97–136): fp32 `min`/`max` over the vector; `scale = (max−min)/15` clamped ≥ 1e-8; `q = clamp(trunc((v−min)/scale + 0.5), 0, 15)` — round-half-up; two codes/byte, low nibble = even index; scale and min rounded to **fp16** and stored.
- **Reconstruction** (decode `triton_turboquant_decode.py:271–299`, full-dequant 322–455): `v̂ = q·fp16(scale) + fp16(min)` in fp32; `k̂ = fp8→fp32` (lossless read of the stored byte).

**Attention math (PROVEN by reading).** Decode stage 1 (lines 87–313): q loaded bf16→fp32 (for K8V4, `q_rot = query` — **no rotation applied, consistent with unrotated stored keys**, launcher 522–528); scores `Σ q·k̂ ·D^-1/2` fp32; classic fp32 online softmax over BLOCK_KV=4 tiles; value accumulation `acc = acc·rescale + Σ p·v̂` fp32; per-split output `acc/l` + `lse = m + log l`. Stage 2 (`triton_decode_attention.py:576–639`) is the standard exact LSE merge over the 32 splits (`tq_max_kv_splits_for_cuda_graph = 32`, config/attention.py:49); empty splits skipped identically on both sides. Net: exactly `softmax(q·K̂ᵀ/√D)·V̂` up to fp32 rounding. Grid is length-independent (split bounds computed in-kernel from the seq_lens tensor) — CUDA-graph replay at any length is structurally sound.

**Error bounds (PROVEN by derivation, confirmed by executed probe `k8v4_probe.py`).**
- Per K element: relative error ≤ **2^-4 = 6.25 %** in the normal range (|k| ≥ 2^-6); absolute ≤ 2^-10 below it (flush region |k| < 2^-10 → rel err up to 1 with abs < 2^-9 — irrelevant to scores). Measured: mean rel 2.3 %, RMS 3.5–4.2 % on N(0,σ) keys.
- Per V element: absolute error ≤ `(max−min)/30 + 15·s·2^-11 + |min|·2^-11`; measured max/range = 0.033628 vs the 1/30 = 0.033333 core term — the fp16-metadata excess is exactly the derived correction. RMS ≈ **0.109·σ_v** (matches theory: E[range of 256 N(0,1)] ≈ 5.8σ, step/√12). This ~9:1 SNR on values is the intrinsic 4-bit cost behind the preset's documented "+1.17 % PPL" — a model-quality tradeoff, not an implementation defect.
- Rounding bias: round-half-up on the bf16 input grid yields a measured **+2.8e-4 mean signed V error (~0.3 % of the quant-noise RMS)**; keys RN-unbiased. Each token is quantized independently — errors do not accumulate across positions or steps; no drift.
- Softmax accumulation over 262,144 positions: score perturbation from FP8 keys measured σ(Δs) ≈ 0.033 logits, max ≈ 0.15 (D=256, unit-scale q/k) → multiplicative softmax-weight distortion ≤ e^{2·max|Δs|}. Attention-output relative error at N = 4,096 / 65,536 / 262,144: **11.0 % / 11.8 % / 14.5 %**, decomposed as ~3.3 % key-induced + ~10–14 % value-induced on iid inputs (the mild N-growth is softmax tail concentration, not arithmetic drift; coherent real-model outputs dilute this further). fp32 online-softmax rounding at these lengths is negligible (~√(2048)·2^-24 per split). **No position- or length-dependent bias exists in the math**: keys are stored post-RoPE (norm-preserving rotations), quantization is per-token.
- Edge cases: all-zero vector → codes 0, reconstructs exactly 0 (the 1e-8 clamp is correct); constant vector → error = fp16 rounding of the constant only; NaN inputs: K stores NaN (propagates), V's `NaN > 1e-8 = False` path launders NaN into finite garbage codes — inconsistent but only reachable after upstream breakage; |v-range| > 982,560 or |min| > 65,504 → **fp16 scale/min overflow to ±inf, unguarded** (unreachable for sane bf16 activations; flagged below).

**Packing/index arithmetic (PROVEN).** Pack/unpack round trip exact on edge patterns (0x0/0xF/alternating/all codes). Slot layout `[0,256) key | [256,384) codes | 384–385 scale | 386–387 min` exactly abuts at stride 388 — no aliasing, no padding gaps. Address math `blk·stride_block + off·stride_pos + head·stride_head (+d)` is int64 throughout store/decode/dequant; store and all readers use strides from the same transposed view (`(num_blocks, block_size, Hk, 388)` → pos-stride 388, head-stride block_size·388), so byte conventions agree by construction; per-lane `block_table` lookups handle page crossings inside a tile. Prefix-cache reuse shares immutable filled blocks — position-absolute RoPE + identical prefix ⇒ identical intended contents; nothing TQ-specific is unsafe. FlyDSL/SoA is hard-gated to AMD gfx950 (`flydsl_turboquant_decode.py:56–74`) — AoS on this deployment, so the SoA/AoS mixing hazard the code warns about cannot arise.

**Chunked-prefill interaction (VERIFIED-BY-READING).** `do_kv_cache_update` stores the chunk *before* attention (attention.py:543/563, 709–733); raw bf16 K/V go straight into the store — the checkpoint's 32 static `k_scale`/`v_scale` tensors load into layer buffers but are **inert** on this path (README claim confirmed; and with an explicit `--kv-cache-dtype` the `kv_cache_scheme`→fp8 auto-override is bypassed, attention.py:281–284). Continuation chunks > 128 tokens: `_continuation_prefill` bulk-dequantizes the cached prefix into the reserved workspace and runs FA2 varlen with cu_seqlens (q_len, seq_len) — FA2's bottom-right causal alignment gives query i exactly keys [0, cached_len+i], matching the explicit SDPA-fallback mask; the current chunk's K/V enter **raw** (dequant tail overwritten before use; positions ≥ seq_len never read). Continuations ≤ 128 tokens run the decode kernel with synthetic per-query seq_lens `cached_len+1+i` — correct causal self-inclusion, but the current chunk is then read back *quantized* (asymmetry noted below). One precision nit: continuation dequant stores V̂ via fp32→fp16→bf16 (kernel `.to(tl.float16)` then implicit store-cast into the bf16 workspace buffer) — a ≤1-bf16-ulp double rounding vs the decode path's direct fp32 use; **identical to the pre-patch value trajectory**, so patch 1 changed no numerics.

## 3. NVFP4 weight dequantization — convention matches checkpoint (VERIFIED-BY-READING + repo's ground-truth audit)

Checkpoint `config.json` group_1: e2m1 packed weights, group 16, e4m3 group scales, fp32 global scales, dynamic-local fp4 activations. Deployed scheme `compressed_tensors_w4a4_nvfp4.py`: `weight_packed` uint8 [out, in/2], `weight_scale` fp8_e4m3 [out, in/16], global scales stored **as divisors** and inverted at load (`weight_global_scale = 1/stored.max()`, `alpha = (1/in_gs)·(1/w_gs)`, lines 110–138); kernel `FlashInferCutlassNvFp4LinearKernel` (`kernels/linear/nvfp4/flashinfer.py`) with dynamic activation quantization via `scaled_fp4_quant(x, input_global_scale_inv)` and swizzled block scales. The dequant contract — `value = E2M1[code] · e4m3(group_scale) / global_divisor`, low-nibble-first, contiguous groups, grid {0, .5, 1, 1.5, 2, 3, 4, 6} with sign bit 0x8 — is exactly the convention of both `scripts/nvfp4_kernel_unit.py` (which pins divisors 2752/161 for the worst layer and *requires* the FlashInfer-CUTLASS selector) and `scripts/audit_weight_quantization.py`, and the latter was validated full-tensor against the official BF16 checkpoint (aggregate rel-L2 0.1082 / cos 0.99415; corroborated directly from `audit-results/source-weight-audit-….json`). That ground-truth match also settles that `actorder: "static"` implies no hidden permutation. The GPU unit's measured M=1/17/129 agreement (rel-L2 ≤ 0.00381, cos ≥ 0.999993) certifies the binary GEMM against dequantized operands; the FlashInfer CUTLASS internals themselves remain binary (ASSUMED correct beyond that measured contract). FP8 (W8A8, channel-wise) layers use the standard scheme with fp32 scale parameters (bf16 checkpoint scales cast exactly on load) — VERIFIED-BY-READING; no per-kernel acceptance unit exists for FP8 linears (gap, below). **BF16 bypass:** quantization attaches only to Linear/embedding modules matched by the target/ignore lists; the 161 norm tensors are plain `nn.Parameter`s on GemmaRMSNorm modules, loaded by direct copy — no quantized path can touch them; vision, `linear_attn.{norm,in_proj_a,in_proj_b}`, `A_log`, `dt_bias`, conv1d are in `ignore` and load unquantized. PROVEN at the census level (probe read dtypes BF16 from the header).

## 5. Gated DeltaNet + chunked prefill — exact state continuity (PROVEN), MRoPE consistency (PROVEN structurally)

**Operator.** From the deployed decode kernel (`fused_sigmoid_gating.py:129–155`), per token in fp32: `g = −exp(A_log)·softplus(a + dt_bias)`, `β = sigmoid(b)`, q/k L2-normalized with eps 1e-6, `S ← e^g·S`, `v' = β(v − S·k)`, `S ← S + v'⊗k`, `o = S·(q/√128)`. Prefill computes identical g/β/l2norm in `fused_post_conv_prep` (`fused_gdn_prefill_post_conv.py:128–149`, L2NORM_EPS=1e-6) feeding the FLA chunk pipeline (`chunk.py:23–86`: local cumsum → KKᵀ/solve_tril WY form → `chunk_gated_delta_rule_fwd_h` → `chunk_fwd_o`; scale default `k_dim^-0.5` matches decode). The chunk algorithm is the literature-standard exact reformulation of the sequential rule (FLA reference implementation vendored verbatim) — VERIFIED-BY-READING; softplus/l2norm implementations differ between phases only at the ≤1-ulp/e^-20 level (both mathematically exact forms).

**Chunk-boundary exactness.** `has_initial_state = context_lens > 0` (`gdn_attn.py:402–416`); each 2048-token engine chunk enters `chunk_gated_delta_rule` with `initial_state = ssm_state[…]` (zeroed only when no prior context) and writes `final_state` back (`qwen_gdn_linear_attn.py:1501–1520`) — **state carried, never recomputed**. Precision of the handoff: in-kernel state is fp32 (`chunk_delta_h.py:88–94,115–130`), `final_state` allocated fp32, and `ssm_state` is fp32 because the Qwen3.5 config handler copies `mamba_ssm_dtype: "float32"` into the cache config (`models/config.py:786–804` → `mamba_utils.py:96–108`); `.to(ssm_state.dtype)` is a no-op. Probe `gdn_fold_probe.py` (executed): splitting the sequential recurrence at 2048 with fp32 state carry is **bit-identical** to the single pass (outputs and final state), while a counterfactual bf16 carry would inject ~8.5e-6 relative error — the deployed fp32 choice is exactly what makes the boundary value-preserving. Further, 2048 ≡ 0 mod FLA_CHUNK_SIZE(64), so the engine-chunked execution partitions tokens into the *same* 64-blocks as a hypothetical unchunked call — even the internal rounding structure coincides. Decay `e^g < 1` strictly (softplus>0) ⇒ contractive state, no growth over 262,144 positions. The width-4 conv state is carried per request through `causal_conv1d_fn/update` (fp32 accumulation, in-fp32 SiLU, `causal_conv1d.py:398–478`) — VERIFIED-BY-READING. Prefix caching runs in mamba `"align"` mode (auto-promoted, `models/config.py:600–637`; `"all"` rejected by the model), where hits resume only at lengths with a stored exact state snapshot (MambaSpec align semantics, `kv_cache_interface.py:687–708`) — no boundary discontinuity by construction. GDN layers receive no positions at all (RoPE-free), so chunking cannot shift them.

**MRoPE.** The full prompt's position triples are computed once per request (`gpu_model_runner.py:1709–1734` via the model's image-aware `_get_mrope_input_positions`) and each chunk merely slices `[:, num_computed : num_computed+n]` (`gpu_model_runner.py:2821–2869`); generated tokens use the delta-continuation formula. Chunked ≡ unchunked positions **by construction**. The interleaved axis map: Triton predicate `(i % 3 == 1) & (i ≤ 3·sec_h)` / `(… == 2) & (≤ 3·sec_w)` (`mrope.py:62–68`) vs the torch helper's strict `<` (mrope.py:226–233) vs HF's `slice(offset, 3·sec, 3)` — all three are **provably identical for every section value** since the bound 3·sec ≡ 0 (mod 3) can never coincide with an index ≡ 1 or 2 (mod 3). PROVEN by congruence (this closes the transcription-only gap in the context unit). Sections [11,11,10] over 32 pairs, rotary dim 64, theta 1e7 — all config-confirmed; text/generated tokens have T=H=W so the map is irrelevant outside image blocks.

## 6. Everything else — units coverage, findings, concerns

**Audit-unit coverage characterization.**
- `turboquant_k8v4_unit.py` (≡ the patched in-tree test): proves, on the real GPU and exact geometry (D=256, 24/4 heads, 37 tokens, 3 blocks incl. partial, 4 splits), byte-exact keys/scales/minima vs an independent encoder, code-exact V4 nibbles with a principled 2e-5 boundary-interval ≤1-step allowance (18 such lanes on the recorded run), and fused-decode agreement (max_abs 0.00381, cos 0.999998) with an explicit fp32 GQA reference over the *stored* representation. It does **not** exercise: long contexts/32-split merges at scale, the two continuation paths, prefix-block reuse, mixed batches, CUDA-graph replay, or quantized-vs-unquantized quality (correctly out of scope).
- `nvfp4_kernel_unit.py`: real worst-error checkpoint layer, kernel-selector-mandatory, independent E2M1/swizzle dequant reference at M=1/17/129. Activation quantization is common-mode between kernel and reference (the unswizzled-scale dequant is the independent layout check); only one layer/kernel; FP8 linears have no analogous unit.
- `qwen38_context_unit.py`: executes the real position builder vs an independent HF-5.15 reimplementation (3 interleaved images, reversed transport order, `max(grid_h,grid_w)` advance, delta continuation) and freezes geometry + the 6,509,559,808-byte identity. Its axis-map check was transcription-level — now closed analytically above. It does not execute the rotary *application* kernel.
- `phase_budget_unit.py`: CPU check of patch-4 stop semantics only.

**Defects / concerns found (none load-bearing for the deployed configuration):**
1. **Unguarded fp16 metadata overflow** in V-quant: per-vector range > 982,560 (or |min| > 65,504) stores inf scale/min → garbage reconstruction, silently. Unreachable for sane bf16 activations; an assert would make it fail-closed. (Theoretical.)
2. **NaN asymmetry**: NaN keys propagate (correct), NaN values are laundered into finite garbage codes via the `scale > 1e-8` clamp. Post-breakage only.
3. **Continuation-path asymmetries**: (a) large continuations double-round V̂ (fp32→fp16→bf16, ≤1 bf16 ulp vs decode); (b) ≤128-token continuation chunks attend to their *own* K/V through the quantized cache while >128 chunks use raw — a small, bounded semantic asymmetry.
4. **Round-half-up V rounding** gives a measured +0.3 %-of-noise-RMS bias; non-accumulating; cosmetic.
5. **Portability hazard**: on SM < 8.9 the same code silently switches keys to `float8e4b15` (max ≈ 1.75) — post-norm keys with gain >1.75 would saturate destructively. Not this GPU (SM 12.0 ⇒ e4nv/E4M3), but worth a guard if the image is ever rehosted.
6. **Unit gaps**: no FP8-linear acceptance unit; no on-GPU chunked-vs-sequential GDN equivalence test; TQ unit narrow as characterized.
7. Doc nits: `docs/qwen38-context-turboquant-audit.md` says prefill stores *after* attention (deployed order is store-first; numerically irrelevant); the 637-vs-622 byte-identical counts across README/doc reconcile as 15 non-BF16 reference-precision tensors.
8. The 264,115-token capacity figure is from engine logs — ASSUMED, but bounded-consistent: an independent bound (total − 48·2 mamba pages of 3,207,168 B)/24,832 = 266,514 tokens ≥ 264,115, difference explicable by page-size unification padding; the live 262,143+1 boundary test covers what matters.
9. Housekeeping: repo HEAD f68f189, clean; `.claude/` empty; upstream model-card benchmark tables are vendor prose, unverifiable locally and not part of the deployment contract.

**Positive robustness findings**: the fp32-weight dtype guard makes wrong-kernel dispatch of offset norms structurally impossible; static KV-calibration scales are inert under `turboquant_k8v4`; slot layout exactly abutting with int64 addressing; length-independent decode grids under CUDA graphs; 2048-chunk ∣ 64-FLA-chunk alignment; positions precomputed-then-sliced.
